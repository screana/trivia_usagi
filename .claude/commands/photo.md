動画で出した回を、そのまま写真投稿の8枚にする。**実際に見て**確認する。

## 始める前に

```bash
git pull
```

**飛ばせない。** 遅れていると `python -m src.photo` は作らずに止まる
(`episode.check_fresh()`)。AGENTS.md には「同じ雑学を2回使うから」と書いてあるが、
写真版が pull を要る理由は別で、**そっちのほうが黙って効く**。

- `--ep` を省くと対象は「**手元で**番号が一番大きい回」。他のマシンで作られた
  新しい回は pull するまで手元に無いので、**古い回で作ってしまう**。
  回が存在する以上エラーにならない
- 台本と記録は追跡されている。pull しないと**更新前の振り・オチ・記録**で作る

件数が合わなければ止まる仕組みは入っているが、**古い回・古い台本はどちらも
件数が合ってしまう**ので素通りする。

```bash
python -m src.photo                # 一番新しい回で8枚作る
python -m src.photo --ep 1         # 過去回で作る
python -m src.photo --html         # PNGを書かず、HTMLだけ作る(レイアウトを詰めるとき)
```

書き出したら `out/photo_preview.html` を**ブラウザで開いて全8枚を見る**。
1枚ずつ見たいときは `episodes/NNN/photos/0N.png` を Read ツールで開く。

## 動画を作った後にやる

**雑学を選び直さない。** 材料は全部その回のものを使う。

| 出すもの | どこから |
| --- | --- |
| 振り / オチ | 台本 `script.json` の `setup` / `punch` |
| 補足 | DBの `content`(`record.json` の id で引く) |
| カテゴリ | `record.json` の `category` |
| イラスト | 回の `images/` と `images/manifest.json` |

なので **`/script` と `/images` と `/trivia --mark` が終わっている回でしか作れない。**
記録が台本と件数が合わなければエラーで止まる。

**画像ファイルは追跡していない。** 別のマシンで作った回は絵がローカルに無く、
「警告: 画像がありません」が出てイラスト無しで描かれる。その回で写真版も出すなら
`/images` で取り直す。

## 見る観点

- **下から300pxはキャプションやボタンに隠れる。** 補足の末尾がそこに入っていないか
- 補足の文字だけ他の枚より明らかに小さい枚がないか。自動縮小が効いた印で、
  その項目は台本側を短くするほうが早い(縮小はブラウザ側で走るので、
  結果のフォントサイズはHTMLにもPNGにも残らない。見比べるしかない)
- 折り返しが文節の途中で切れていないか。動画と同じ BudouX を通しているが、
  1行に収まらない文節だけは途中で折れる
- 1枚目の「N選」と実際の枚数が合っているか
- イラストが縦長すぎて余白が空きすぎていないか

## 出典表記

**写真側で新しく持つものは無い。** イラストは動画と同じものなので、
`images/manifest.json` に出所が残っている。`/publish` がそこからクレジットを書く。
写真投稿の説明文にも同じクレジットを貼る。

## 直すとき

数値と文言は `src/config.py` の `PHOTO_*` だけを触る。
表紙の文言も `PHOTO_COVER_LEAD` / `PHOTO_COVER_BIG` / `PHOTO_COVER_WORD` にある。

レイアウトを何度も試すなら `--html` を付けて、`out/photo_preview.html` を
ブラウザで再読み込みしながら詰める。ブラウザを8回起動しなくて済む。

組み立てを触ったら確認を通す。

```bash
python test_photo.py
```
