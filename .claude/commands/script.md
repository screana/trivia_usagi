アプリのデータベースから雑学を持ってきて `script.json` を作る。

**元データは裏取り済み**なので、web検索での事実確認は不要。
やることは**選定と、振り/オチへの組み立て**の2つ。

## 1. 候補を見る

```bash
python -m src.trivia --list 20 --full
```

`hee_count` は、アプリ内で「へぇ」ボタンが押された強さの合計(1人あたり1〜10)。
**実際の反応が数字で残っているので、面白さの推測より当てになる。**
使用済みのものは自動で除外される。

## 2. 7つ選ぶ

上位から採るのが基本。そのうえで次を見る。

- **ジャンルが偏っていないか。** `category` が同じものばかりにしない
- **オチの言い回しが揃いすぎていないか。** 「〜ではない」が並ぶと単調になる
- **振りが画面2行に収まるか。** 長い題材は避ける

**hee_count が近ければ、ジャンルが散る方を選ぶ。**

## 3. 振りとオチに割る

DBの `title` は**オチそのもの**に近い形で書かれている。
これを「振り」と「オチ」に割るのは機械的にはできないので、`content` を読んで組む。

```
title  : ネギトロの由来にはネギもトロも関係ない
  ↓
setup  : ネギトロの由来には
punch  : ネギもトロも関係ない
```

割るときの目安。

- **振りは主語だけにする。** オチを言ってしまわない
- **オチは短く言い切る。** 説明を足さない(補足は動画に入らない)
- 数字や固有名詞の読み方は `/voicecheck` で確認する。
  DBの表記のままだと誤読することがある

## 4. script.json を書く

```json
{
  "title": "...",
  "items": [
    { "setup": "ネギトロの由来には", "punch": "ネギもトロも関係ない" }
  ]
}
```

**タイトルは釣りすぎない。** 動画の中身の範囲で書く。

## 5. 使用済みに記録する

```bash
python -m src.trivia --mark 112 16 172 32 67 23 63 --note "第1回"
```

これを忘れると次回また同じものが候補に出る。

## 終わったら

```bash
python -m src.preview --item 1     # 画面に収まるか見る
python -m src.voice --check        # 読み方を確認する
```

振り・オチが画面からはみ出すなら、**レイアウトではなく文言を短くする。**

## 補足: 選定の偏りについて

`hee_count` は古い雑学ほど積み上がっている(id との相関 -0.65)。
単純な降順だと古いものから消費されていく。当面はそれで問題ないが、
在庫が減って新しいものばかり残るようになったら、ID帯ごとの相対評価に
切り替える(README の「雑学の選定」を参照)。
